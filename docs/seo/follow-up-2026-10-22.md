### Воспроизводимые команды (из вложенного корня проекта)

```bash
npm run gsc:check
npm run gsc:report -- --start 2026-09-21 --end 2026-10-18
npm run gsc:inspect -- --url https://www.sorgfaltbau.de/de/services/trockenbau-halle --url https://www.sorgfaltbau.de/ru/services/trockenbau-halle
npm run seo:check -- --base https://www.sorgfaltbau.de
```

Второй пример повторяет исходный период для проверки воспроизводимости, а не
измеряет новые результаты: для follow-up подставить явные новые даты. Инспекцию
запустить для всех URL свежего sitemap (в аргументах повторять `--url`), минимум
для всех 12 исходных исключений. Ошибки API сохранять и отмечать как непроверенные,
а не считать их исключением из индекса.

Сравнивать только final web-данные одинакового свойства, одинаковую длину периода,
те же фильтры/агрегацию. Зафиксировать полноту данных и последний доступный день;
3-дневный буфер не гарантирует полноту. Не сравнивать неполный октябрь с полным
сентябрём. На +7/+14 допустимо описать раннюю динамику, но пересекающиеся окна
28 дней не доказывают эффект. Для Germany/mobile использовать соответствующие
разрезы; их пересечение требует отдельной одинаково отфильтрованной выгрузки для
обоих периодов. Не выводить город из страны и не считать позицию стабильным рангом.

Запросы Google частично скрыты. Не суммировать их как весь трафик и не утверждать,
что все нераскрытые клики — бренд/боты. Клики GSC ≠ звонки ≠ реальные заявки.
Источник 16 исторических записей формы не установлен. Не приписывать их SEO.
